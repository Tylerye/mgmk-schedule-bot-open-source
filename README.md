тяжёлый PDF parsing только после изменения metadata и автоматически поддерживает
сообщения и закреп в Telegram-группе.

## Личное расписание

Откройте бота в личных сообщениях, отправьте `/start`, выберите язык и свою группу
Кнопки открывают сегодня, завтра и ближайший день, настройки позволяют сменить группу и отключить автообновления или автоматический закреп
Закреп в личных сообщениях переключается в 16:30 по Минску, групповая часть использует отдельные настройки

Для своего развёртывания используйте [DEPLOYMENT.md](DEPLOYMENT.md), для отдельной личной подсистемы - [PERSONAL.md](PERSONAL.md)
Публичные примеры конфигурации не содержат рабочих ключей

## Возможности

- точный parsing предметов, кабинетов и преподавателей из PDF без OCR;
- отдельная типизированная сетка уроков, перемен, 20- и 40-минутных обедов,
  кураторского и информационного часа;
- новая сетка звонков с 28.09.2026, применяемая к ближайшим расписаниям
  автоматически и без перепубликации прошлых дней;
- немедленная публикация нового расписания без дублей;
- редактирование существующего сообщения при исправлении PDF;
- короткое «Что изменилось» при исправлении PDF: предмет, кабинет,
  преподаватель, время, добавленные и убранные уроки;
- daily pin rotation в `16:00` строго по `Europe/Minsk`, с уведомлением;
- снятие только собственного предыдущего schedule pin;
- compact live-view, скрывающий завершённые события, и inline-переключатель
  `Показать всё` / `Только актуальное`;
- `/next` — короткая справка: текущее или ближайшее занятие, кабинет и минуты
  до начала/конца; на перемене показывает её название, после занятий не подставляет завтра;
- `/day` — сводка на завтра: первый урок, начало и конец занятий, количество
  уроков, дополнительные занятия, обед и большие перемены внутри учебного дня;
- отдельное незакреплённое уведомление о замене предмета, добавлении или отмене
  урока в уже опубликованном расписании на сегодня или будущую дату;
- `/all` и `!важно текст` — объявления владельца и куратора с подтверждением
  и упоминаниями известных участников; `/all_test` упоминает только вызывающего;
- восстановление публикаций, pin и live-view после restart или outage;
- неблокирующая проверка `can_pin_messages`: без права бот продолжает polling,
  публикацию и live-view, а после выдачи права сам начнёт закреплять;
- persistent state в Cloudflare D1, SHA-256, timeout/retry/backoff;
- сериализованные source/reconcile циклы без overlap;
- отдельная быстрая обработка справочных команд webhook: они читают snapshot D1
  без ожидания глобального state lock; дедупликация защищена lease конкретного update;
- structured JSON logging и `/healthz`;
- личные кабинеты трёх преподавателей с доступом по username → постоянный ID,
  персональным расписанием, кнопками, уведомлениями и закрепом;
- личные расписания всех групп из каталога: RU/EN, поиск группы, настройки и автообновления;
- настройка доступа: закрытый пилот или регистрация всех пользователей в ЛС;
- неизвестные Telegram-группы не обслуживаются автоматически.

## Конфигурация

Нужен Node.js 22.13+. Скопируйте `.env.example` в `.env`. Обязательны только:

- `BOT_TOKEN` — токен из BotFather;
- `ADMIN_USER_ID` — числовой Telegram ID администратора.

Основные production defaults:

```dotenv
GROUP_NAME=8Са
DISPLAY_GROUP_NAME=8-Сба
TIMEZONE=Europe/Minsk
SCHEDULE_POLL_SECONDS=60
PIN_SWITCH_TIME=16:00
STATE_PATH=./data/state.json
HEALTH_PORT=8080
HEALTH_HOST=127.0.0.1
```

`.env` и `data/` игнорируются Git. Токен нельзя передавать аргументом командной
строки, сохранять в README, test snapshots или логах.

## LOCAL DEVELOPMENT

```powershell
npm ci
npm test
npm run dry-run
```

Dry-run читает реальный источник и парсит PDF, но не вызывает Telegram API.
Локальный polling (для отдельного тестового бота или согласованного cutover):

```powershell
npm start
```

Если у токена уже настроен webhook, локальный процесс завершится до
публикации сообщений. Работающий production обслуживается Cloudflare;
для обычной локальной проверки используйте `npm run dry-run`.

Wrangler закреплён точной версией в `package-lock.json`; патчи `sharp` и
`undici` для локального Miniflare заданы в `overrides`. CI проверяет Node 22/24,
зависимости, тесты и сборку Worker. `npm run cf:tail` показывает ограниченный
диагностический поток без тел запросов, заголовков и токенов.

## Подключение Telegram-группы

Создайте своего бота в BotFather, затем:

1. Добавьте бота в нужную Telegram-группу.
2. Для автоматического закрепления сделайте его администратором с правом
   `Pin Messages`. Без этого права остальные функции продолжают работать.
   Group Privacy можно оставить включённой.
3. От аккаунта с `ADMIN_USER_ID` отправьте `/setup` в группе.
4. После подтверждения выполните `/status` от того же администратора.

`/setup` сохраняет отрицательный group `chat_id` и сразу запускает reconcile.
Команды `/today`, `/tomorrow` и `/latest` работают только в настроенной группе;
`/next` доступна всем участникам этой группы и использует сохранённое расписание
на сегодня по `Europe/Minsk`, без дополнительного парсинга и изменений закрепа.
Меню команд Telegram настраивается для подключённой группы через
`node --env-file=.env scripts/configure-bot-commands.js` с `GROUP_CHAT_ID` в окружении.
Участники видят `/next`, `/day`, `/today`, `/tomorrow`, `/latest`; владелец также `/status`.
Telegram сохраняет меню самостоятельно; оно не требует повторного вызова при restart.
Владелец и куратор дополнительно видят `/all` первым
пунктом и `/all_test`. Для готового сообщения или фото нужно ответить на него
командой `/all`; новое объявление можно начать с `!важно` в тексте или подписи.
Префикс `!важно` остаётся в исходном сообщении: Bot API не позволяет боту
редактировать чужие сообщения в обычной группе. Если нужен чистый текст,
отправьте объявление без префикса и ответьте на него `/all`. Оригиналы не удаляются.
Бот спрашивает подтверждение на 5 минут, затем отвечает упоминаниями, не меняя
закреп. Только автор вызова может подтвердить; массовый вызов — не чаще раза в минуту.
Список получателей пополняется авторами сообщений и кнопкой «Я в группе»;
записываются только ID и имена, текст переписки не сохраняется. Ушедшие и боты
исключаются. Полный охват и звук уведомления не гарантируются настройками Telegram.
После миграции `0004_attention.sql` первый Cron автоматически проверяет права,
обновляет webhook (без сброса pending updates), меню и однократно размещает кнопку
регистрации. Очередь объявлений независима от schedule state lock. Неоднозначная
отправка сохраняется как `uncertain` и не повторяется; только явный 429 повторяется
после `retry_after`. Локальный процесс использует тот же обработчик и отдельную
SQLite `${STATE_PATH}.attention.sqlite` (Node >=22.13), не изменяя JSON расписания.
После миграции `0005_acknowledgements.sql` только новые объявления получают
«✅ Ознакомился», персональную «📋 Сводку», ручное «🔔 Напомнить» и «Закрыть».
Аудитория фиксируется при отправке; знаменатель включает только успешно
отправленные части. Подтверждение добровольное, действует 24 часа или до закрытия.
Сводка доступна владельцу и куратору через `ephemeral_message_parameters`,
только нажавшему; при отказе API публичной замены нет. Большие списки показаны
страницами по 6 имён: стрелки «⬅️ / ➡️» редактируют одно персональное сообщение
через `editEphemeralMessageText`, не отправляя новую страницу сообщением.
Повторное открытие использует ту же активную персональную сводку. Сессия действует
30 минут, привязана к группе, получателю и `ephemeral_message_id`; чужие кнопки
отклоняются. Если Telegram уже убрал сообщение, открыть новое можно повторным
нажатием «Сводка»/«Список», но не автоматической публичной заменой.
Ссылки «К объявлению» у оповещения и напоминания ведут на исходное сообщение
автора; сами Telegram-упоминания остаются привязаны к сообщению бота.
Напоминание требует отдельного подтверждения, возможно через 10 минут и только
один раз, с общим ограничением массовых оповещений раз в минуту. Уже подтвердившие
и ушедшие проверяются заново перед отправкой. Двойные нажатия защищены SQL CAS,
счётчик объединяет быстрые нажатия и восстанавливается Cron из базы.
Состояние отправки сохраняется до API-вызова; неоднозначный timeout не повторяется.
`/all_test` использует весь сценарий только для вызывающего. Старые объявления,
текст исходных сообщений и закрепы не изменяются.
Для добровольного набора владелец или куратор отвечает на сообщение с задачей
командой `/need N` (1–30, по умолчанию пять). Бот размещает один ответ с кнопками
«Я пойду», «Не смогу», персональным «Списком» и «Закрыть набор».
Первые нажавшие занимают места; уникальная запись и атомарная проверка лимита
защищают от повторов и одновременной записи на последнее место. Отмена и выход
из группы освобождают место, повторная запись становится последней в очереди.
Заполненный набор не закрывается окончательно: место доступно после отмены.
Набор действует 24 часа после публикации либо до ручного закрытия; после закрытия
состав фиксируется. Текст задачи не сохраняется, только ссылки на сообщения и
метаданные участников. Список видят только владелец и куратор персонально;
при недоступности приватного API публичной замены нет. Миграция —
`0006_recruitments.sql`, восстановление и объединение счётчика — через ту же
независимую очередь Worker/локального бота. Отправка `uncertain` не повторяется.
`/day` выбирает строго завтрашнюю календарную дату по `Europe/Minsk`:
если её расписание не опубликовано, другой день не подставляется.
Для 8-Сба обедом называется только первый предусмотренный сеткой перерыв
после третьего урока (в четверг — после информационного часа, 11:20–11:40).
Остальные 20- и 40-минутные перерывы, обозначенные в таблице как обеды,
в сообщениях показываются как большие перемены. Это правило оформления:
время занятий, исходный parser state и schedule hashes не меняются.
Кабинеты показываются обычным шрифтом, обед и все перемены подчёркнуты
как в актуальном, так и в полном представлении прошедших занятий.
`/status` дополнительно ограничен администратором. Личные сообщения вне
подключённых учительских кабинетов и команды в чужих группах молча игнорируются;
болтовня не вызывает ответов, но
метаданные участников подключённой группы пополняют список оповещения. Update offset
продвигается.
Webhook отбрасывает неавторизованные личные сообщения, чужие группы, неизвестные команды и
повреждённый JSON до очереди; сохраняет только нужные командные метаданные.
Права объявлений проверяются по положительным безопасным числовым ID;
регистрация привязана к исходной кнопке, подтверждение — к автору и сообщению.

## Мониторинг и публикация

Каждый цикл выполняет дешёвый list + `HEAD` и сравнивает file ID,
`Last-Modified`, `ETag` и размер. Неизменённый PDF не скачивается и не парсится.
После реального изменения проверяются magic bytes, SHA-256, дата документа и
normalized schedule hash.

Будущее расписание публикуется сразу обычным сообщением. Исправление сначала
редактирует уже существующее сообщение с пометкой `Расписание обновлено` и
кратким списком конкретных отличий. Для сравнения бот хранит опубликованную
версию в D1; старые записи без неё пока показывают обычную пометку об
обновлении. Новая публикация используется только если Telegram больше не
разрешает edit.

После успешного обновления бот отдельно сообщает о заменах предметов,
добавленных и отменённых уроках. Все изменения одной версии объединяются;
кабинет, преподаватель и время сами по себе уведомление не вызывают.
Первичная публикация и изменения прошлых дней не вызывают уведомлений.
Уведомление не закрепляется. Его intent и результат сохраняются в JSON state D1.
Ожидающие уведомления восстанавливаются после restart. При неоднозначном сетевом
сбое или прерывании отправки результат помечается `uncertain`, повторная отправка
блокируется и появляется warning в логах: Telegram не предоставляет idempotency key
для `sendMessage`, поэтому в таком случае доставка не гарантируется.
Явный `429` повторяется после `retry_after`, постоянный отказ `4xx` не зацикливается.

До `16:00 Europe/Minsk` закреплено расписание текущего дня. После cutoff бот
переключает pin на уже опубликованное расписание завтра. Если его ещё нет,
текущий pin остаётся. Расписание, найденное после `16:00`, сразу публикуется и
становится новым pin. Закрепление выполняется с Telegram-уведомлением.

Право проверяется через `getChatMember`. Отсутствие `can_pin_messages` и отказ
`pinChatMessage` записываются как warning, не прерывают polling и не вызывают
повторную публикацию. Проверка повторяется автоматически раз в пять минут.

Закреплённое сообщение пересчитывается раз в минуту. В compact mode события с
`event.end <= now` скрыты; в full mode завершённые уроки отмечены галочкой
и жирной строкой без курсива.
Сравнение учитывает полную дату и IANA timezone, поэтому завтрашнее расписание,
закреплённое сегодня, не фильтруется преждевременно.

## Напоминания об объявлениях

В подключённой группе владелец бота и куратор могут ответить на текст или фото
командой `/remind завтра 08:00`, `/remind сегодня 15:00` или
`/remind 05.10.2026 08:00`. Время всегда `Europe/Minsk`; относительная дата
сохраняется сразу. Команда есть только в их персональных меню; суффикс
`@mgmk_8cba_schedule_bot` поддерживается. Для отмены — кнопка под подтверждением
либо `/remind отмена` ответом на исходное объявление; отменять могут оба.

Минимум до отправки — минута, максимум — 30 дней; одно ожидающее напоминание
на объявление и максимум десять на группу. Изменение времени: отменить старое,
создать новое. Напоминание — один ответ на исходное сообщение с кнопкой-ссылкой,
без текста объявления, упоминаний и закрепления. Если исходное сообщение удалено,
отправки без контекста нет.

Миграция `0007_event_reminders.sql` хранит только ссылки, числовые ID, время и
состояния, без переписки. Worker использует минутный Cron, локальная версия —
независимую минутную проверку. Отправка не гарантируется секунда в секунду.
После сбоя допустима задержка до 15 минут включительно; старые записи становятся
`missed`. Атомарная резервация защищает от конкурирующих проверок и отмены.
Явный `429` и подтверждённый JSON-отказ Telegram `5xx` повторяются в пределах
этого окна. Сетевые/неоднозначные gateway-сбои и прерванная отправка становятся
`uncertain`: автоматического повторения нет. Итог обновляется в сообщении
подтверждения; восстановление никогда не повторяет неизвестную отправку.
Логи: `event_reminder_sent`, `event_reminder_missed`,
`event_reminder_send_stopped`, `event_reminder_abandoned_send_uncertain`.

## Health и логи

`GET http://127.0.0.1:8080/healthz` показывает без секретов: startup,
доступность Telegram, последние source poll/change/parser success, наличие
настроенной группы, текущую pinned date, `canPinMessages` и следующий цикл. `/status` даёт
сокращённый вариант администратору в группе.

Ключевые события логов: `source_poll_started`, `source_unchanged`,
`new_source_detected`, `schedule_parsed`, `schedule_changed`,
`telegram_schedule_posted`, `telegram_schedule_edited`, `pin_rotated`,
`live_message_updated`, `callback_view_changed`, `retry`, `error`.

## PRODUCTION

Целевой вариант не требует billing profile или банковской карты:

- Cloudflare Workers Free: Telegram webhook, минутный Cron, live/reconcile и pin rotation;
- Cloudflare D1 Free: persistent state, jobs и защита от дублей;
- GitHub Actions Free: Node/pdf.js parser, запускаемый при изменении исходного PDF.

PDF parsing намеренно не выполняется внутри Worker: на реальном 7-страничном PDF
он занял 47–109 мс CPU при лимите Workers Free 10 мс. Подробная архитектура,
секреты, перенос существующего state и порядок безопасного webhook cutover описаны
в [DEPLOYMENT.md](DEPLOYMENT.md).
