# Безопасность

Не публикуйте токены, базы, личные сообщения, ID участников и рабочие конфиги
в issues, pull requests или логах CI. Для примеров используйте вымышленные данные.

Перед commit запускайте `npm run check:privacy`. Для распакованного архива
без Git можно выполнить `node scripts/check-repository-privacy.js --directory`.
Проверка ищет известные форматы секретов и запрещённые файлы, но не гарантирует
обнаружение произвольного секрета или содержимого старой Git-истории.

Об уязвимости сообщайте через GitHub Private vulnerability reporting, если
владелец включил эту функцию. Иначе сначала запросите приватный канал у владельца,
не раскрывая способ эксплуатации публично. При утечке отзовите ключ у провайдера
и замените его в хранилище секретов. Удаление строки из нового коммита
не отзывает ключ и не очищает историю.

Не запускайте polling и webhook одновременно с одним токеном. Не переносите
чужие D1 snapshots и права доступа в свой экземпляр.
